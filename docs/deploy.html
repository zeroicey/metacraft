MetaCraft 部署指南

本指南涵盖 MetaCraft 后端服务（Spring Boot）和鸿蒙（HarmonyOS）前端应用的完整部署流程。

系统架构

🏗️ MetaCraft 系统架构

🎯 HarmonyOS 客户端

鸿蒙原生应用，提供 AI 对话和应用生成功能

🌐 Spring Boot API

RESTful API 服务，处理业务逻辑和 AI 集成

🗄️ PostgreSQL

主数据库，存储用户、应用、会话等核心数据

📦 MinIO

对象存储服务，存储生成的应用文件

🤖 LangChain4j + Qwen

AI 引擎，提供智能对话和应用生成能力

🐳 Docker

容器化部署，简化环境配置和扩展

数据库配置

2.1 创建数据库

MetaCraft 使用 PostgreSQL 作为主数据库。在部署前需要创建数据库和用户。

方式一：使用 psql 命令行

# 连接到 PostgreSQL
sudo -u postgres psql

# 创建数据库
CREATE DATABASE metacraft;

# 创建用户并设置密码
CREATE USER metacraft_user WITH PASSWORD 'your_secure_password';

# 授予权限
GRANT ALL PRIVILEGES ON DATABASE metacraft TO metacraft_user;

# 切换到数据库并授权 schema 权限
\c metacraft;
GRANT ALL ON SCHEMA public TO metacraft_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO metacraft_user;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO metacraft_user;

方式二：使用 Docker 运行 PostgreSQL

# 启动 PostgreSQL 容器
docker run -d \
  --name metacraft-postgres \
  -e POSTGRES_DB=metacraft \
  -e POSTGRES_USER=metacraft_user \
  -e POSTGRES_PASSWORD=your_secure_password \
  -v postgres_data:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:15-alpine

# 验证运行状态
docker ps | grep metacraft-postgres

2.2 数据库优化配置

为了获得更好的性能，建议在 postgresql.conf 中进行以下优化：

# postgresql.conf 优化配置

# 连接设置
max_connections = 200
shared_buffers = 256MB  # 约为物理内存的 1/4
effective_cache_size = 1GB
maintenance_work_mem = 64MB

# 写入性能
wal_buffers = 16MB
checkpoint_completion_target = 0.9
max_wal_size = 1GB

# 查询性能
random_page_cost = 1.1
effective_io_concurrency = 200
default_statistics_target = 100

# 日志设置
log_destination = 'stderr'
logging_collector = on
log_directory = 'log'
log_filename = 'postgresql-%Y-%m-%d.log'
log_statement = 'ddl'
log_min_duration_statement = 1000

2.3 创建扩展和表结构

MetaCraft 使用 Flyway 进行数据库迁移，应用启动时会自动创建表结构。确保数据库用户具有足够的权限。

# 授予 extensions 权限（如需要）
\c metacraft;
GRANT ALL ON SCHEMA public TO metacraft_user;

-- 启用 UUID 扩展（如果需要手动操作）
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
应用首次启动时，Flyway 会自动执行 src/main/resources/db/migration/ 目录下的所有迁移脚本。

MinIO 配置

3.1 MinIO 简介

MetaCraft 使用 MinIO 作为对象存储服务，用于存储用户生成的应用文件、头像等二进制数据。MinIO 是 S3 兼容的对象存储，可以完全兼容 AWS S3 API。

3.2 使用 Docker 部署 MinIO

# 启动 MinIO 容器
docker run -d \
  --name metacraft-minio \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin123 \
  -v minio_data:/data \
  -p 9000:9000 \
  -p 9001:9001 \
  minio/minio:latest \
  server /data --console-address ":9001"

# 验证运行状态
docker ps | grep metacraft-minio

3.3 MinIO 控制台配置

MinIO 启动后，可以通过以下方式访问：

  • API 端点: http://your-server:9000
  • 控制台: http://your-server:9001
  • Access Key: minioadmin
  • Secret Key: minioadmin123
生产环境请务必修改默认的 Access Key 和 Secret Key，并使用强密码。

3.4 创建存储桶

登录 MinIO 控制台后，创建以下存储桶：

存储桶名称 用途 策略
apps 存储用户生成的应用文件 公共读
avatars 存储用户头像 公共读
logos 存储应用图标 公共读
templates 存储应用模板 私有

使用 mc 命令行工具创建存储桶：

# 安装 MinIO Client
wget https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc
sudo mv mc /usr/local/bin/

# 配置 mc 连接到本地 MinIO
mc alias set myminio http://your-server:9000 minioadmin minioadmin123

# 创建存储桶
mc mb myminio/apps
mc mb myminio/avatars
mc mb myminio/logos
mc mb myminio/templates

# 设置存储桶策略（公共读）
mc anonymous set download myminio/apps
mc anonymous set download myminio/avatars
mc anonymous set download myminio/logos

3.5 MinIO 高级配置

启用 TLS/HTTPS

# 使用自签名证书
docker run -d \
  --name metacraft-minio \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin123 \
  -v minio_data:/data \
  -v /path/to/certs:/root/.minio/certs \
  -p 9000:9000 \
  -p 9001:9001 \
  minio/minio:latest \
  server /data --console-address ":9001" --certs-dir "/root/.minio/certs"

配置生命周期策略

# 配置 30 天后自动删除过期文件
mc ilm rule add myminio/apps --expiry-days 30

配置分布式存储（生产环境）

# 4节点分布式 MinIO 集群
docker run -d \
  --name minio-node1 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin123 \
  -v /data1/minio:/data/minio/data \
  minio/minio:latest \
  server http://minio-node{1...4}/data/minio/data \
  --console-address ":9001"

后端应用配置

4.1 环境变量配置

MetaCraft 后端通过环境变量进行配置。以下是所有可用的配置项：

变量名 默认值 说明
SERVER_PORT 8080 服务端口
DB_URL - PostgreSQL 连接地址
DB_USERNAME - 数据库用户名
DB_PASSWORD - 数据库密码
DB_DRIVER org.postgresql.Driver JDBC 驱动类
API_KEY - DashScope API Key（阿里云 Qwen 模型）
MODEL_NAME qwen-plus 使用的 AI 模型名称
JWT_SECRET - JWT 密钥（至少 256 位）
JWT_EXPIRATION 8640000000 JWT 过期时间（毫秒）
APP_STORAGE_PATH data 应用文件本地存储路径
ZHIPU_API_KEY - 智谱 API Key（可选）
YUANMENG_SHARED_ROOM shared 共享房间名称
YUANMENG_NANOBOT_TOKEN 123456 Nanobot 认证令牌
OPENCODE_ENABLED true 是否启用 OpenCode 功能

4.2 配置文件示例

方式一：使用 .env 文件

# 创建 .env 文件
cat > .env << 'EOF'
# 数据库配置
DB_URL=jdbc:postgresql://localhost:5432/metacraft
DB_USERNAME=metacraft_user
DB_PASSWORD=your_secure_password

# JWT 配置
JWT_SECRET=your-256-bit-secret-key-change-this-in-production
JWT_EXPIRATION=8640000000

# AI 模型配置
API_KEY=your-dashscope-api-key
MODEL_NAME=qwen-plus

# 存储配置
APP_STORAGE_PATH=/data/metacraft/apps

# 服务端口
SERVER_PORT=8080
EOF

方式二：使用 application.yaml

# 在 src/main/resources/application.yaml 中配置
spring:
  datasource:
    driver-class-name: org.postgresql.Driver
    url: ${DB_URL:jdbc:postgresql://localhost:5432/metacraft}
    username: ${DB_USERNAME:metacraft_user}
    password: ${DB_PASSWORD}
  flyway:
    enabled: true
    baseline-on-migrate: true
    locations: classpath:db/migration

server:
  port: ${SERVER_PORT:8080}

jwt:
  secret: ${JWT_SECRET:change-this-secret-key-in-production-at-least-256-bits}
  expiration: ${JWT_EXPIRATION:8640000000}

langchain4j:
  community:
    dashscope:
      chat-model:
        model-name: ${MODEL_NAME:qwen-plus}
        api-key: ${API_KEY}
      streaming-chat-model:
        model-name: ${MODEL_NAME:qwen-plus}
        api-key: ${API_KEY}

app:
  storage:
    path: ${APP_STORAGE_PATH:data}

4.3 安全配置

JWT 密钥必须使用强随机字符串，建议至少 32 个字符的随机字符串。 
# 生成安全的 JWT 密钥
# 方法 1：使用 openssl
openssl rand -base64 32

# 方法 2：使用 uuid
uuid -v 4 | tr -d '-'

Docker 部署

5.1 构建 Docker 镜像

创建 Dockerfile 文件：

# 构建阶段
FROM maven:3.9-eclipse-temurin-21 AS builder

WORKDIR /app

# 复制 pom.xml 和源码
COPY apps/api/pom.xml apps/api/
COPY apps/api/src apps/api/src

# 构建应用
WORKDIR /app/apps/api
RUN mvn clean package -DskipTests

# 运行阶段
FROM eclipse-temurin:21-jre-alpine

WORKDIR /app

# 复制构建产物
COPY --from=builder /app/apps/api/target/*.jar app.jar

# 创建应用数据目录
RUN mkdir -p /data/apps /data/templates

# 设置时区
RUN apk add --no-cache tzdata && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

# 暴露端口
EXPOSE 8080

# 启动应用
ENTRYPOINT ["java", "-jar", "app.jar"]

5.2 Docker Compose 完整部署

创建 docker-compose.yml 文件：

version: '3.8'

services:
  # PostgreSQL 数据库
  postgres:
    image: postgres:15-alpine
    container_name: metacraft-postgres
    environment:
      POSTGRES_DB: metacraft
      POSTGRES_USER: metacraft_user
      POSTGRES_PASSWORD: your_secure_password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U metacraft_user -d metacraft"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - metacraft-network

  # MinIO 对象存储
  minio:
    image: minio/minio:latest
    container_name: metacraft-minio
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin123
    volumes:
      - minio_data:/data
    ports:
      - "9000:9000"
      - "9001:9001"
    command: server /data --console-address ":9001"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3
    networks:
      - metacraft-network

  # MetaCraft 后端服务
  api:
    build:
      context: .
      dockerfile: Dockerfile
    image: metacraft-api:latest
    container_name: metacraft-api
    environment:
      DB_URL: jdbc:postgresql://postgres:5432/metacraft
      DB_USERNAME: metacraft_user
      DB_PASSWORD: your_secure_password
      JWT_SECRET: your-256-bit-secret-key-change-this-in-production
      API_KEY: your-dashscope-api-key
      MODEL_NAME: qwen-plus
      APP_STORAGE_PATH: /data/apps
      SERVER_PORT: 8080
    volumes:
      - app_data:/data
    ports:
      - "8080:8080"
    depends_on:
      postgres:
        condition: service_healthy
      minio:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    restart: unless-stopped
    networks:
      - metacraft-network

volumes:
  postgres_data:
  minio_data:
  app_data:

networks:
  metacraft-network:
    driver: bridge

前置条件

  • JDK 21+ 已安装并配置 JAVA_HOME
  • Maven 3.9+ 已安装
  • PostgreSQL 15+ 已运行
  • MinIO 已配置

构建步骤

# 进入后端项目目录

./mvnw clean package -DskipTests

./mvnw spring-boot:run

# 生产环境打包（跳过测试）
cd apps/api
./mvnw clean package -Pproduction -DskipTests

# 运行 JAR
java -jar target/metacraft-api-1.0.0.jar \
  --spring.datasource.url=jdbc:postgresql://localhost:5432/metacraft \
  --spring.datasource.username=metacraft_user \
  --spring.datasource.password=your_password \
  --jwt.secret=your-secret-key \

HarmonyOS 应用开发需要使用华为提供的 DevEco Studio IDE。以下是安装步骤：

下载与安装

平台 下载方式 系统要求

macOS 从华为开发者联盟下载 macOS 10.15+
Linux 从华为开发者联盟下载 Ubuntu 20.04+

DevEco Studio 配置

# 首次启动配置
1. 运行 DevEco Studio
2. 选择 "Do not import settings"
3. 设置 JDK 路径（需要 JDK 17）
4. 配置 Node.js 路径（用于构建前端资源）
5. 配置 ohpm 路径（鸿蒙包管理器）
